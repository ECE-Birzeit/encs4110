## Example: Basic LCD Driver Implementation

![LCD Connection Schematic](/image-3.png)

The figure above shows the complete wiring diagram for connecting the 16×2 LCD module to the TM4C123 microcontroller using 4-bit mode. The connections are:
- **Power**: VDD to VBus, VSS to Ground, V0 to contrast potentiometer
- **Control**: RS to PB0, E to PB2, RW to Ground (write-only)
- **Data**: D4-D7 to PB4-PB7 respectively
- **Backlight**: A to VBus, K to Ground

The contrast potentiometer (typically 10 kΩ) allows adjustment of the display visibility - rotating it changes the voltage on V0 pin between 0V and VDD.

### Code Explanation

**Initialization Sequence**

The `LCD_Init()` function implements the complete 4-bit initialization:
1. Enables the PORTB clock, then polls `SYSCTL->PRGPIO` bit 1 until it reads back as ready before touching `GPIOB` (the peripheral-ready alternative to the fixed-`NOP` delay used in [Experiment 5](./5)), and configures the pins as outputs. The driver also configures PB1 (`RW`) as an output and drives it low in software, the code-level equivalent of wiring RW to ground, so no physical wire from PB1 to the LCD's RW pin is required.
2. Waits 50 ms for LCD power-on stabilization
3. Sends `0x03` (upper nibble) three times with delays (8-bit mode reset)
4. Sends `0x02` (upper nibble) to switch to 4-bit mode
5. Sends configuration commands: `0x28` (4-bit, 2 lines), `0x0C` (display on), `0x06` (entry mode), `0x01` (clear)

**Nibble Transmission**

The `LCD_SendNibble()` function:
- Masks out current data bits (PB4-PB7)
- Places the 4-bit nibble on PB4-PB7 (shifted left by 4)
- Generates the enable pulse: E high → short delay → E low → short delay. The LCD latches D4–D7 on the falling edge of E, and E must stay high for at least 450 ns, so `LCD_PulseDelay()` busy-waits about 2 µs.

**Command vs. Data**
- `LCD_Command()`: Sets RS=0, sends upper nibble, sends lower nibble
- `LCD_Data()`: Sets RS=1, sends upper nibble, sends lower nibble

**Cursor Positioning**

The `LCD_SetCursor(row, col)` function calculates the DDRAM address:
```c
address = (row == 0) ? 0x80 + col : 0xC0 + col;
```
Then sends the address as a command.

**String Printing**

The `LCD_Print(str)` function iterates through the string and sends each character using `LCD_Data()`.

**Timebase: `millis()` and `delay_ms()`**

The LCD needs waits between steps (50 ms at power-up, 2 ms after a command, 1 ms after a character), so the driver includes a small timebase built on SysTick:

- `LCD_Init()` calls `SysTick_Config(SystemCoreClock / 1000)`, so SysTick reloads and interrupts every 1 ms.
- `SysTick_Handler()` increments `ms_ticks`, and `millis()` returns it: the number of milliseconds since `LCD_Init()`. It wraps after about 49 days.
- `delay_ms(n)` waits by counting SysTick reloads with the `COUNTFLAG` bit rather than watching `ms_ticks`. Inside another interrupt handler (a button press, say) SysTick_Handler can't run, so `ms_ticks` would stop and a delay based on it would never finish. `COUNTFLAG` is set by the hardware regardless, so `delay_ms()` and every `LCD_*` function also work inside interrupt handlers.

::: warning lcd.c owns SysTick
Because `lcd.c` defines `SysTick_Handler`, don't write your own in a project that uses the LCD (the linker will report it as defined twice). Use `millis()` for timing instead, as shown below.
:::

To do something periodically without blocking the main loop, compare `millis()` against the last time it ran:

```c
uint32_t last = millis();

while (1)
{
    if (millis() - last >= 500)   // every 500 ms
    {
        last += 500;
        // update the display here
    }
    // the rest of the loop keeps running in between
}
```

The subtraction `millis() - last` stays correct even when the counter wraps around, because both values are unsigned 32-bit numbers.

## Tasks

### Task 1: Display Your Name and ID

Update the main program to display your name on the first line and your student ID on the second line of the LCD.

**Requirements:**
- Clear the display
- Set cursor to line 1, column 0
- Print your name (up to 16 characters)
- Set cursor to line 2, column 0
- Print your student ID

**Hint:**
```c
LCD_Clear();
LCD_SetCursor(0, 0);  // Line 1
LCD_Print("Your Name");
LCD_SetCursor(1, 0);  // Line 2
LCD_Print("ID: 1234567");
```

### Task 2: Button-Controlled Name Scrolling

Write a program that displays your name on the LCD and allows the user to scroll the text left or right using the two on-board push buttons (SW1 and SW2).

**Requirements:**
- Display your name on line 1
- Configure SW1 (PF4) and SW2 (PF0) with GPIO interrupts (falling edge, internal pull-up)
- When SW1 is pressed: Shift display left (command `0x18`)
- When SW2 is pressed: Shift display right (command `0x1C`)
- The display should not scroll automatically; only respond to button presses

### Task 3: Bidirectional Continuous Scrolling

Write a program that displays your name on line 1 and your student ID on line 2, with continuous scrolling in opposite directions after a button press.

**Requirements:**
- Display your name on line 1 and ID on line 2
- Initially, the display is static (no scrolling)
- When SW1 is pressed, start continuous scrolling:
  - Line 1 scrolls right
  - Line 2 scrolls left
- Pressing SW1 again stops the scrolling
- Scroll at a fixed interval (e.g., every 500 ms) using `millis()` in the main loop, as in the timebase example above

**Hint:**
The display-shift commands from Task 2 (`0x18`/`0x1C`) move **both** lines together, so they cannot scroll the two lines in opposite directions. Instead, keep each line's text in a 16-character buffer padded with spaces. Every 500 ms, rotate line 1's buffer one position right and line 2's buffer one position left, then rewrite both lines with `LCD_SetCursor()` and `LCD_Print()`.
